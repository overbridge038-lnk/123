# 誤品照合アプリ

製造現場で、**現品の写真**と**マスター写真**を比べて、品番の取り違え（誤品）を **OK / NG** で判定するアプリです。
Androidタブレットの Chrome で動き、ホーム画面に追加すればアプリのように使えます。

- 判定の仕組み：写真を AI（MobileNetV2）で数値の並び（特徴量）に変え、2枚の「似ている度合い（類似度）」を計算します。顔認証と同じ考え方です。
- **マスター（品番・マスター写真）はクラウド（Firebase）で全員が共有**します。登録・変更・削除ができるのは**管理者だけ**で、それ以外の人は照合のみです。ログインした許可済みの人にしか写真は見えません。
- 照合の計算（AI）は**各タブレットの中**で行います。マスターは各タブレットにコピー（キャッシュ）されるので、**オフライン（電波なし）でも照合できます**。AIモデルや Firebase の部品も自前ファイルとして同梱しており、外部CDNに依存しません。
- 照合履歴は、そのタブレットの中にだけ保存されます（クラウドには送りません）。

## 1. 公開する手順（GitHub Pages・初心者向け）

アプリは「ただのファイルの集まり」なので、GitHub Pages という無料サービスに置くだけで使えるようになります。

1. GitHub のこのリポジトリを開きます。
2. 上のタブ **Settings**（設定）をタップします。
3. 左のメニューから **Pages** を選びます。
4. **Build and deployment** の **Source** を **Deploy from a branch** にします。
5. **Branch** を `main`（このアプリのファイルが入っているブランチ）、フォルダを `/ (root)` にして **Save** を押します。
6. 1〜2分待ってページを更新すると、上の方に `Your site is live at https://（あなたの名前）.github.io/（リポジトリ名）/` と表示されます。これがアプリのアドレスです。

> ブランチが `main` でない場合は、このアプリのファイルを `main` ブランチに取り込んでから（プルリクエストをマージ）、上の手順をしてください。

## 1.5 クラウド（Firebase）の準備【管理者が最初に1回だけ】

無料の Spark プラン（クレジットカード登録なし）で動きます。**Cloud Storage は使いません**（写真は縮小した JPEG として Firestore に保存します）。
Android の Chrome で https://console.firebase.google.com を開き、Google アカウントでログインして進めてください。画面の表記は更新で多少変わることがあります。

### ① プロジェクトを作る
1. **「プロジェクトを作成」**（または「プロジェクトを追加」）をタップ。
2. プロジェクト名に好きな名前（例：`gohin-app`）を入れて **続行**。
3. 「Google アナリティクス」は **オフ** にして **プロジェクトを作成**。完了したら **続行**。

### ② ログイン（Authentication）を設定する
1. 左のメニュー（見えないときは左上の ☰）から **構築 → Authentication** を開き、**始める** をタップ。
2. **Sign-in method（ログイン方法）** タブで **メール／パスワード** をタップ → 一番上の **有効にする** をオン（「メールリンク」はオフのまま）→ **保存**。
3. **設定** タブ → **ユーザー アクション** を開き、**「作成（登録）を有効にする」のチェックを外して保存**。
   これで、外部の人が勝手にアカウントを作れなくなります。（この項目が見つからなくても、③のセキュリティルールで守られます。）

### ③ データベース（Firestore）を作る
1. 左のメニューから **構築 → Firestore Database** → **データベースを作成**。
2. ロケーションは **asia-northeast1（東京）** を選んで **次へ**。（あとから変更できないので注意）
3. **本番環境モードで開始** を選んで **作成**。
4. 作成後、**ルール** タブを開きます。中身を**すべて消して**、このリポジトリの **`firestore.rules`** ファイルの内容を貼り付け、**公開** をタップします。
   - GitHub でリポジトリの `firestore.rules` を開き、右上の **コピー（Copy raw file）** ボタンでコピーできます。
   - このルールで「名簿（members）に載っているログイン済みの人だけ読める／管理者だけ書ける」が強制されます。**これを貼らないと、写真を守れません。**

### ④ アプリ用の設定値を取り出して貼り付ける
1. 左上の **歯車 → プロジェクトの設定** → 下の **マイアプリ** で **ウェブ（`</>`）** をタップ。
2. アプリのニックネーム（例：`gohin`）を入れて **アプリを登録**（「Firebase Hosting も設定」はチェックしない）。
3. 表示される `firebaseConfig` の中の値（apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId）をメモ（長押しコピー）します。
4. GitHub のこのリポジトリで **`firebase-config.js`** を開き、右上の **鉛筆（編集）** をタップ。`ここに貼り付け` の部分を、それぞれの値（`'` と `'` の間）に置き換えて **Commit changes**（コミット）します。
   - この値が公開されても問題ありません（守っているのはセキュリティルールです）。
5. 1〜2分待つと GitHub Pages に反映されます。

### ⑤ ユーザー（6人分）を作る
1. Firebase の **Authentication → ユーザー** タブ → **ユーザーを追加**。
2. メールアドレスとパスワードを入れて **追加**。6人分繰り返します。メールアドレスは実在しなくても構いません（例：`tablet1@example.com`）。**英字は小文字**で作ってください。
3. 本人（各タブレット）にメールアドレスとパスワードを伝えます。パスワードを忘れたときは、管理者が Firebase コンソールのユーザーの右の **︙** から対応します。

### ⑥ 名簿（members）を作る【ここが「誰が管理者か」の設定】
1. **Firestore Database → データ** タブ → **コレクションを開始**。
2. コレクション ID に `members`（半角・小文字）と入れて **次へ**。
3. **ドキュメント ID** に、⑤で作った**メールアドレスをそのまま（小文字で）**入れます。
4. フィールドを1つ追加：フィールド名 `role`、タイプ **string**、値は **管理者なら `admin`、照合だけの人なら `member`**。**保存**。
5. 6人全員分、**ドキュメントを追加**で繰り返します。（管理者は限定した数名だけに `admin` を付けます）
- 名簿に載っていない人は、ログインできても写真は見られません。人を外したいときは、そのドキュメントを削除（＋ Authentication のユーザーも削除）します。

### 無料枠について
Spark プランの目安：読み取り 1日5万回／書き込み 1日2万回／保存 1GB。6人で使う程度なら、通常は十分です。アプリは「変更があった写真だけ」を取得するようにしています。写真は1枚あたり最大400KB・1品番20枚までです。

## 2. タブレットで使い始める手順

1. タブレットの **Chrome** で、上のアドレスを開きます。**最初の1回は必ずWi-Fiなどネットに繋いだ状態**で開いてください（AIモデル約14MBとマスター写真を端末に保存するため）。
2. **メールアドレスとパスワード**でログインします（一度ログインすれば、ログアウトするまで保たれます）。
3. 画面上部の黄色い帯「AIモデルを読み込み中…」が消え、右上に「☁ 同期済み」と出たら準備完了です。
4. 初めてカメラを使うとき、「カメラの許可」が出たら **許可** を押します。
5. Chrome 右上の **︙（メニュー）→「ホーム画面に追加」**（または「アプリをインストール」）を押します。ホーム画面にアイコンができます。
6. 以後はそのアイコンから起動します。電波がなくても使えます。
   - 「設定」タブの「アプリ情報」に **オフライン動作：準備OK** と出ていれば大丈夫です。

## 3. 使い方

### ① マスター写真を登録する（管理者のみ・最初に1回）
「登録」タブは**管理者にだけ表示**されます。登録した内容は、数秒〜数分で全員のタブレットに反映されます（電波があるとき）。登録・削除には**ネット接続が必要**です。
1. 下の **「登録」** タブ → **「＋ 品番を追加」** で品番（と品名）を入力します。
2. **「カメラで撮影して追加」** で、正しい品物を撮影します。四角の**真ん中**に品物が入るようにしてください。
3. 写真は自動で縮小・圧縮（長辺800px以内・約400KB以下）してクラウドに保存されます。置き方・明るさ・背景は、**実際に照合するときと同じ**にするのがコツです。**角度や向きを少し変えて2〜3枚**登録すると安定します。
4. 写真ファイルがある場合は **「写真ファイルから追加」** も使えます。

### ② 現品を照合する（毎回・全員）
1. **「照合」** タブで上の品番ボタンを押し、品番を選びます。マスター写真が左に表示されます。
2. 右のカメラの四角の中に現品を入れ、**「撮影して照合」** を押します。
3. 大きく **OK（緑）** または **NG（赤）** と、類似度が表示されます。ブザーとバイブでも知らせます。
4. **「次の照合へ」** で次の品物へ。結果は自動で履歴に保存されます。

### ③ 履歴とCSV
- **「履歴」** タブで一覧を確認できます（品番・OK/NGで絞り込み可）。写真をタップすると、そのときの現品写真を見られます。
- **「CSVで書き出し」** で、表示中の履歴を CSV ファイルとして保存します（Excel でそのまま開けます）。

## 4. しきい値の調整（とても大切）

OK / NG は「類似度が**しきい値以上なら OK**、未満なら NG」で決まります。標準は **70%** です。
このAIは一般的な画像用で、あなたの現場の部品専用に学習したものではないため、**実際の品物で調整が必要**です。

1. 正しい品物を何度か撮影し、類似度を見ます（例：85〜95%）。
2. わざと誤品（似た別品番）を撮影し、類似度を見ます（例：50〜70%）。
3. 両者の**真ん中あたり**を、「登録」タブ → その品番 → **しきい値** に設定します。
4. 誤品なのに OK になる場合はしきい値を**上げ**、正しい品物なのに NG になる場合は**下げ**ます。

**精度を上げるコツ**：同じ場所・同じ明るさで撮る／背景を無地にする／マスターを複数枚登録する／カメラを品物に近づけて大きく写す。
色や小さな刻印だけが違う誤品は、見分けにくいことがあります。導入前に、実際の誤品パターンで必ず試してください。

## 4.5 検査ポイント方式（形状照合）

「色が同じで形が似た別品番」は、写真全体の類似度だと高い点が出て見逃すことがあります。そこで、**形の違いが出る場所（検査ポイント）**だけを、輪郭（エッジ）で比べる方式を追加しています。色は使いません。

**管理者の登録（品番ごと・マスター写真ごと）**
1. 「登録」タブ → 品番を開き、マスター写真の **「◎ 検査ポイント」** ボタンを押します。
2. 写真の上を **指でなぞると四角** ができます（1枚に最大20個）。四角の中を動かすと移動、角の丸を動かすと大きさが変わります。
3. 四角を選ぶと、**名前**・**しきい値**（「標準」なら設定タブの値）・**重要度**（必須／参考）を決められます。不要な四角は「この四角を削除」。
4. **保存** を押すとクラウドに保存され、全員のタブレットに配られます。座標は写真に対する比率（0〜1）で保存します。
- マスター写真が複数ある品番は、写真ごとにポイントを登録できます。照合時は、**位置合わせが最もうまくいった写真**のポイントを使います（位置合わせは最大8枚まで試します）。
- ポイントを登録した写真が1枚も無い品番は、従来どおり全体の類似度で判定します。

**照合のしくみ**
1. 現品の写真を、マスター写真に **位置合わせ**（拡大縮小・回転・平行移動）します。
2. ポイントごとに輪郭の一致度（0〜100%）を計算し、しきい値以上なら OK です。**必須のポイントが全部 OK のときだけ総合 OK**。「参考」は結果に表示するだけです。
3. 結果画面では、現品写真に **緑（OK）・赤（NG）の枠**が重なります。「参考」の NG は破線の赤枠です。
4. 位置合わせができなかったときは「位置合わせできませんでした」と出て NG になります（現品を四角の中央に置いて撮り直してください）。

**設定タブ**：「検査ポイントの標準しきい値」と、「全体の類似度も合格条件に加える（併用）」のオン／オフがあります（この2つは端末ごとの設定です）。

**コツ**：ポイントは「穴」「先端」「折れ曲がり」など、**輪郭がはっきり出る場所**に置いてください。何も無い平らな場所に置くと、ノイズで点数が不安定になります。しきい値の初期値（70%）は目安です。**実際の正しい品と誤品を何枚か撮って、履歴の点数を見ながら調整してください。**

## 5. ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` / `style.css` / `app.js` | アプリ本体（画面・見た目・動き） |
| `cloud.js` | ログイン・クラウドとの同期・管理者の書き込み |
| `shape.js` | 検査ポイント方式の計算（位置合わせ・形状の比較）。`node tests/shape.test.js` で動作確認できます |
| `firebase-config.js` | **Firebase の設定値（ここに貼り付ける）** |
| `firestore.rules` | Firestore のセキュリティルール（コンソールに貼り付けて使う） |
| `vendor/firebase.js` | Firebase SDK 12.19.0（Authentication + Firestore を1ファイルにまとめたもの・Apache-2.0） |
| `sw.js` | オフラインで動かすための仕組み（Service Worker） |
| `manifest.json`, `icons/` | ホーム画面に追加するための設定とアイコン |
| `vendor/tf.min.js` | AIを動かすライブラリ（TensorFlow.js 4.22.0・Apache-2.0） |
| `model/` | AIモデル本体（MobileNetV2・Apache-2.0。Google が TensorFlow.js 用に公開しているもの） |

## 6. アプリを更新したとき

ファイルを書き換えたら、`sw.js` の `const CACHE = 'gohin-v4';` の番号を `v5`、`v6` …と上げてください。（`firebase-config.js` だけは、書き換えれば自動で新しいものが使われます）上げないと、タブレットが古いファイルを使い続けます。更新後はアプリを一度閉じて開き直します。

## 7. 注意

- 履歴はタブレットの中だけにあります。**Chromeの「サイトデータを消去」やアプリの削除をすると、その端末の履歴は消えます**（マスターはクラウドにあるので、再ログインすれば取得し直します）。履歴は定期的にCSVで書き出してください。
- まだ一度も同期していない端末では、マスターがありません。最初は必ずネットに繋いで同期してください。
- 名簿から外された人は、次にネットに繋いだとき、端末内のマスターのコピーも消えます。
- **クラウド対応前に、端末だけに登録していた品番・写真**がある場合は、管理者でログインして「設定」タブの **旧データの移行** を押すと、クラウドへ移せます。
- 管理者が品番を変更・削除すると、各タブレットには次に同期したとき反映されます。
- カメラは https で配信されたページでのみ使えます（GitHub Pages は https です）。
